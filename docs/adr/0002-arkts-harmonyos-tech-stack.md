# 0002: 选择ArkTS + HarmonyOS技术栈

## 状态

Accepted

## 背景

需要选择适合鸿蒙图文音频创作工具的技术栈。目标是充分利用鸿蒙生态优势，提供原生体验。

## 决策

选择 **ArkTS + HarmonyOS SDK** 作为核心技术栈。

### 理由

1. **鸿蒙原生体验**：ArkTS是鸿蒙官方推荐的开发语言，能够充分利用鸿蒙系统能力
2. **生态优势**：直接访问鸿蒙分布式能力、服务卡片、原子化服务等特性
3. **性能优化**：原生开发可以更好地优化性能，特别是音频和图像处理场景
4. **长期支持**：华为官方持续投入，社区生态不断完善

### 放弃的选项

- **Java/Kotlin**：兼容性好但无法充分利用鸿蒙新特性
- **Flutter/RN**：跨平台能力强但鸿蒙生态整合受限

## 后果

- 优点：
  - 最佳的鸿蒙原生体验
  - 充分利用鸿蒙生态能力
  - 更好的性能表现
- 缺点：
  - 开发人员需要学习ArkTS语言
  - 与其他平台代码复用性较低

## 影响范围

- 整个项目的技术架构
- 开发工具链选择（DevEco Studio）
- 人才招聘和培训
